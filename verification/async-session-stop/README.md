# Session inbox ownership: bounded model checks

`AsyncSessionStop.tla` models one running turn, one `/stop`, and one independent automation submission. `current.cfg` is the historical behavior at `53a556585`: the command removed whatever inbox was registered when cleanup returned. `no-second-drain.cfg` removes that operation. The old worker still cancels its own deferred automation; the new worker is free to start as soon as its inbox is installed. Under weak fairness for worker steps and returning cleanup, accepted automation must resolve, and old cleanup must not remove a replacement inbox.

Run [TLC 2.19 from TLA+ v1.7.4](https://github.com/tlaplus/tlaplus/releases/tag/v1.7.4) with `java -cp <tla2tools.jar> tlc2.TLC -config <config> AsyncSessionStop.tla` from a scratch copy of this directory. The historical configuration breaks the safety invariant; to independently reproduce the temporal violation, run it again without the `INVARIANT` line in a scratch copy. The no-second-drain configuration exhausts 13 distinct states. Deadlock checking is disabled because terminal states legitimately have no new work; the temporal property detects a stranded accepted job. These are handwritten abstractions, not verification of the Python source. The Python replay is `test_stop_does_not_strand_automation_submitted_during_cleanup` in `tests/agent/test_session_inbox_controls.py`.

`DeferredDuringDrain.tla` captures the next boundary: a queued command's cancellation completion can suspend after the deferred batch has been taken. `drain-baseline.cfg` admits late work into that retiring inbox and strands it. `drain-retire-first.cfg` detaches the inbox before notifying and exhausts seven distinct states. The Python replay blocks a real `TurnCompleted` subscriber for a queued `/compact`; `test_automation_arriving_during_queue_cancellation_is_not_stranded` reproduces the orphaned waiter on the first PR commit and completes on the new ownership model.

`ShutdownAdmission.tla` checks the shared inbox registry across two session keys. `shutdown-baseline.cfg` admits a submission outside the shutdown snapshot; `shutdown-fenced.cfg` closes admission before taking that snapshot and exhausts eight distinct states. The Python replay holds an already-cancelling provider turn while `aclose()` starts, then attempts to submit automation to another session. The new submission is rejected before an inbox or worker is created. This check covers worker admission, not process or store shutdown liveness.

`SharedWorkerLifetime.tla` interleaves `/stop` and shutdown while an already-cancelling worker is still unwinding. `worker-baseline.cfg` lets shutdown proceed to resource teardown without that worker. `worker-join.cfg` keeps the worker visible until exit and exhausts six distinct states. The Python replay holds a provider's cancellation cleanup; on baseline, shutdown closes session state while the old turn still needs it. The revised runtime joins without issuing a second cancellation. The model assumes the worker can finish cleanup and excludes forced shutdown after a timeout.
